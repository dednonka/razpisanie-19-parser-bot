# Расписание школы — Telegram-бот

Бот следит за папкой в Облаке Mail.ru, куда школа выкладывает расписание в виде `.xlsx`, и раздаёт его в Telegram по кнопкам: дата → класс → буква.

Есть два режима подключения к Telegram:
- **обычный** (`schedule_bot.py`) — через Bot API по HTTPS, для сетей без блокировок;
- **через MTProto-прокси** (`schedule_bot_mtproto.py`) — через [Telethon](https://github.com/LonamiWebs/Telethon), для сетей, где Bot API напрямую недоступен. В этом режиме бот умеет автоматически подбирать рабочий MTProto-прокси из Telegram-канала.

## Возможности

- Автоматически подхватывает новые файлы в папке облака и убирает удалённые — обновлять вручную ничего не нужно.
- **Замечает правки в уже загруженных файлах.** Если файл в облаке заменили под тем же именем, бот увидит это при ближайшей проверке (раз в 10 минут) или по команде `/update`.
- Понимает и обычные файлы «на один день», и файл-мастер сразу на всю неделю (с блоками `ПОНЕДЕЛЬНИК / ВТОРНИК / ...` в одном листе) — показывается отдельной кнопкой с выбором дня недели.
- Корректно разбирает объединённые ячейки: актовый зал на несколько классов, экскурсии на весь день, подгруппы предмета через `/`.
- **По понедельникам** первой строкой у всех классов, у которых в этот день есть уроки, добавляется `0. 8:00 - 8:30 Разговоры о важном`.
- **Пропуски («окна») показываются явно** (только между первым и последним уроком дня):

  ```text
  3. 10:10 - 10:50 русский 24 каб
  4. -
  5. 11:50 - 12:30 физика 7 каб
  ```

- Поиск «когда у класса будет предмет» — показывает ближайший день по недельному расписанию.
- Обратный отсчёт до каникул / до конца каникул (даты задаются в `school_calendar.py`).
- Погода на главном экране (по умолчанию — Курган, источник [wttr.in](https://wttr.in), кэш 15 минут). При ошибке сети строка погоды просто не показывается.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `schedule_bot.py` | Парсер `.xlsx`, логика экранов и бот на обычном `requests` (Bot API) |
| `schedule_bot_mtproto.py` | Тот же бот, но подключение к Telegram через MTProto-прокси (Telethon), автоподбор прокси, парсинг канала |
| `school_calendar.py` | Даты каникул (обновляются вручную раз в год) |
| `test_change_detection.py` | Офлайн-проверка: ловит ли бот правки в файле, корректны ли «Разговоры о важном» и пропуски |

## Требования и установка

- Python 3.10+

```bash
pip install requests openpyxl
```

Для MTProto-версии дополнительно:

```bash
pip install telethon
```

## Запуск

### Вариант 1 — прямой доступ к Telegram (Bot API)

```bash
export BOT_TOKEN="токен_от_BotFather"
python schedule_bot.py
```

### Вариант 2 — через MTProto-прокси (Telethon)

```bash
export BOT_TOKEN="токен_от_BotFather"
export API_ID="число_с_my.telegram.org"
export API_HASH="хэш_с_my.telegram.org"

python schedule_bot_mtproto.py
```

`API_ID` и `API_HASH` берутся в [my.telegram.org](https://my.telegram.org) → *API development tools*.

**Прокси в этом режиме можно не задавать вручную.** Если не указаны `MTPROXY_LINK` / `MTPROXY_SECRET`, бот сам возьмёт свежий MTProto-прокси из канала-источника (по умолчанию [`https://t.me/MTProxy4free`](https://t.me/MTProxy4free)), подберёт рабочий и сохранит его в `proxy_state.json` — при следующем запуске начнёт с сохранённого. При потере связи прокси автоматически переключается.

Если нужно задать прокси вручную (или источник недоступен):

```bash
# целиком ссылкой
export MTPROXY_LINK="tg://proxy?server=HOST&port=PORT&secret=SECRET"

# или по частям (MTPROXY_HOST/PORT необязательны, по умолчанию 127.0.0.1:1443)
export MTPROXY_SECRET="hex_секрет"
export MTPROXY_HOST="127.0.0.1"
export MTPROXY_PORT="1443"
```

Секрет в ссылке может быть в hex или base64url — бот приводит его к нужному виду сам.

### Проверка парсера без запуска бота

```bash
python schedule_bot.py --debug
```

## Переменные окружения (MTProto-версия)

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `BOT_TOKEN` | — (обязательно) | Токен бота от @BotFather |
| `API_ID` | — (обязательно) | Число с my.telegram.org |
| `API_HASH` | — (обязательно) | Строка с my.telegram.org |
| `MTPROXY_LINK` | — | Готовая ссылка `tg://proxy?server=...&port=...&secret=...` (вместо параметров ниже) |
| `MTPROXY_SECRET` | — | Секрет прокси (hex/base64url) |
| `MTPROXY_HOST` | `127.0.0.1` | Хост прокси (если задан `MTPROXY_SECRET`) |
| `MTPROXY_PORT` | `1443` | Порт прокси (если задан `MTPROXY_SECRET`) |
| `PROXY_SOURCE` | `https://t.me/MTProxy4free` | Канал-источник со свежими `tg://proxy?...` ссылками |
| `PROXY_AUTOSWITCH` | `1` (вкл.) | Автосмена прокси при потере связи (`0` — выключить) |
| `PROXY_CHECK_INTERVAL` | `30` | Как часто проверять живость прокси, сек. |
| `PROXY_STATE_FILE` | `proxy_state.json` | Файл, где запоминается рабочий прокси |
| `TG_PROXY` | — | HTTP(S)-прокси для загрузки веб-страницы канала-источника, если она недоступна напрямую |
| `PARSING_MTPRTO` | — | Канал для парсинга постов (напр. `@name` / `t.me/name`); не задан — парсер выключен |
| `PARSING_LIMIT` | `20` | Сколько последних постов держать в памяти |
| `PARSING_INTERVAL` | `300` | Как часто обновлять посты канала, сек. |
| `PARSING_SESSION` | `parser_session` | Имя файла сессии пользовательского аккаунта (для парсинга канала) |

## Команды бота (MTProto-версия)

| Команда | Действие |
| --- | --- |
| `/start` | Показать главное меню/расписание |
| `/update` | Принудительно обновить данные из облака |
| `/channel`, `/news` | Показать последние посты канала, заданного в `PARSING_MTPRTO` |

> `/channel`/`/news` — это парсинг **контента** указанного канала. Источник MTProto-прокси (`PROXY_SOURCE`) командой не меняется — он задаётся переменной окружения при запуске (по умолчанию уже `https://t.me/MTProxy4free`).

## Как работает автоподбор MTProto-прокси

1. При старте: берётся сохранённый рабочий прокси из `proxy_state.json`, иначе — из `MTPROXY_LINK`/`MTPROXY_SECRET`, иначе бот сам запрашивает канал `PROXY_SOURCE` и берёт прокси из самых свежих постов.
2. Источник читается как публичная страница `t.me/s/<канал>` (извлекаются все `tg://proxy?...` ссылки, приоритет у новых постов). Если страница недоступна по HTTPS — запасной путь: чтение канала через Telethon-клиент.
3. Кандидаты проверяются (TCP-доступность + реальное подключение); FakeTLS-секреты (`ee…`) пробуются в последнюю очередь. Рабочий прокси применяется и сохраняется.
4. Фоновый watchdog периодически проверяет связь и при повторных сбоях переключает прокси на следующий рабочий из канала.

## Как бот ловит изменения в расписании

Раз в 10 минут (`REFRESH_SECONDS`) и по команде `/update` бот:

1. получает список файлов из папки в облаке;
2. скачивает каждый файл целиком и считает SHA-256 от содержимого;
3. сравнивает хэш с предыдущим: совпал — пропускает, изменился/новый — парсит заново и обновляет данные;
4. файлы, которых в папке больше нет, удаляет из базы.

Если новая версия файла не скачалась или не разобралась, остаётся прежняя версия, а в лог пишется ошибка — один проблемный файл не мешает обновлению остальных.

## Запуск в Termux (Android)

Чтобы система не усыпляла бота в фоне:

```bash
termux-wake-lock
```

и отключите оптимизацию батареи для Termux в настройках Android.

Автоперезапуск при падении:

```bash
while true; do python schedule_bot_mtproto.py; sleep 5; done
```

Перезапуск раз в двое суток (страховка, не необходимость):

```bash
while true; do timeout 172800 python schedule_bot_mtproto.py; sleep 5; done
```

Сессии (`bot_session`, при парсинге канала — `parser_session`) хранятся на диске, повторно входить после перезапуска не нужно. При самом первом запуске парсера канала (`PARSING_MTPRTO`) Telethon попросит номер телефона и код из Telegram.

## Проверка

Офлайн (без сети):

```bash
python test_change_detection.py
```

Скрипт сам создаёт `.xlsx`, вносит правку и проверяет, что бот её заметил. Ожидается 9 ✅ и код выхода 0.

На реальной папке: замените файл с тем же именем в облаке, отправьте `/update` (или подождите до 10 минут) — в логе должна появиться строка `Файл изменился: <имя>`, а расписание в боте обновится.

## Настройка под свою школу

- **Папка с расписанием:** в `schedule_bot.py` — константа `FOLDER` (идентификатор публичной папки Облака Mail.ru).
- **Каникулы:** даты в `school_calendar.py`.
- **Погода:** `KURGAN_LAT`, `KURGAN_LON` и `WEATHER_TTL` в `schedule_bot.py` (координаты города и время кэша). Пороги смайлов температуры задаются в `weather_line()`.

## Безопасность

`BOT_TOKEN`, `API_ID`/`API_HASH` и секреты/ссылки MTProto-прокси передавайте **только через переменные окружения** — не храните их в коде и не коммитьте в репозиторий. Добавьте в `.gitignore` файлы сессий и состояния, например:

```gitignore
*.session
*.session-journal
proxy_state.json
```
